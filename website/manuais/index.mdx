# Guias

Esta seção é escrita à mão e versionada; a [Referência](/referencia/) e as páginas de
[Testes](/testes/) são geradas a cada build. Os guias explicam **como usar** e **como
interpretar** o que o gerador mostra.

  faz e não faz, contrato de erros e como o site é montado a partir do código.

  comandos de verificação.
- [Publicação no GitHub Pages e manutenção automática](/guias/publicacao) — pipeline,
  ambiente local, variáveis, contratos editoriais e solução de problemas.

## A documentação em números

| Camada | Como é produzida | O que garante |
|---|---|---|
| Guias | escrita manual, versionada | explicação e contexto |
| Referência | extração estática do código | nomes, expansões, guards, usos |
| Testes | extração dos casos em disco | entradas, saídas, negativos, avisos |
| Projeto | importação de `docs/` e README | histórico, decisões e relatórios |
| Internos | extração de tools/tests | transpilador, harness e scripts |

```bash
# reconstruir o site do zero
python3 -m venv .venv
.venv/bin/python -m pip install -r tools/documentacao/requirements.txt
cd website && npm ci && npm run build
```

## Como os guias evitam promessas vazias

Cada afirmação sobre comportamento aponta para uma página gerada, um teste ou um
documento datado. Quando não há execução registrada, o texto diz isso explicitamente —
por exemplo, MSVC é **avaliado**, não “suportado”. Se um guia contradizer o código, o
código e a página gerada vencem, e o guia deve ser corrigido.

## Perguntas frequentes

### Por onde começo se nunca usei BASICGOL?

Comece por [Começar](/guias/comecar): instale um compilador C11, rode `make`, escreva o
programa mínimo e compile. Só depois avance para o caminho M1.

```c
#include <basicgol.h>

INICIO
    ESCREVAL("ola, mundo");
FIM
```

### Qual é a diferença entre “Guias”, “Referência” e “Projeto”?

Guias explicam o uso; a Referência é gerada do código atual; Projeto preserva
especificação, decisões e relatórios históricos. Uma página de referência descreve o que o
fonte faz agora; um relatório descreve o que foi executado em uma fase.

### Preciso ler a especificação para programar?

Não para começar. A referência e os guias bastam para o uso diário. A especificação é
útil quando você precisa saber por que uma construção existe, qual é o contrato de erro ou
se algo está fora do escopo.

### Onde encontro exemplos prontos?

Em [Exemplos](/exemplos/), com fontes versionados e saídas douradas quando existem. Eles
também são compilados por `make exemplos`.

```bash
make exemplos
```

### Os guias são atualizados automaticamente?

Não. Eles são escritos à mão e copiados para o build. O gerador atualiza a referência, os
testes, os exemplos e a importação de `docs/`; se um guia ficar desatualizado, ele deve ser
corrigido no próprio arquivo.

### Como sugiro uma correção na documentação?

Abra um pull request alterando o guia em `website/manuais/` ou o contrato em
`tools/documentacao/contratos.json`, rode o gerador e inclua o resultado de
`npm run build` na descrição. O build trata links quebrados como erro.

```bash
python3 tools/gerar_documentacao.py --strict
cd website && npm run build
```
